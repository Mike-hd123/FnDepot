# Auth / Codex 登录：UI 原型设计（UI Spec）

> 来源：`prototype.html`（静态 HTML 原型，与同目录文档同源）。本文把原型的布局、组件、交互固化成设计规格，供实现参考。视觉细节以原型为准，后续可迭代。

## 1. 页面骨架：渠道管理双 Tab

- 页面标题「渠道管理」，副标题随 tab 切换：
  - API tab：「配置上游 API 供应商与调度优先级」
  - Auth tab：「登录各厂商订阅账号，作为上游路由候选」
- Tab 栏在标题下（underline 风格，对齐 SettingsPage）：`◎ API 渠道 (n)` `🔑 Auth 账号 (n)`。
- 头部操作按钮随 tab 联动：
  - API tab：`导出` `导入 ▾` `＋ 新建渠道`
  - Auth tab：`🔑 登录账号` `⇧ 从 auth.json 导入`

## 2. Auth tab 布局（自上而下）

```
┌────────────────────────────────────────────────┐
│ Provider 一排（pill 横排，参考 LLM 使用页）         │
│   [codex ●] │ [claude] [kiro] [kimi] 规划中       │
├────────────────────────────────────────────────┤
│ 说明文字（登录后账号作为路由候选，消耗订阅额度）        │
├────────────────────────────────────────────────┤
│ ⚠️ 风险提示 banner（常驻，ADR-29 固定文案）          │
├────────────────────────────────────────────────┤
│ 账号卡片网格（2 列，对齐 ApiKeysPage 卡片）          │
│   [账号卡片]  [账号卡片]                           │
│   [账号卡片]  [空槽「＋ 登录 Codex 账号」]           │
└────────────────────────────────────────────────┘
```

### 2.1 Provider 一排
- pill 圆角横排，带 provider 色点；当前仅 `codex` 可点（激活态绿色实底），`claude / kiro / kimi` 灰置 + 「规划中」小标（ADR-12 多 provider 预留）。
- 分隔竖线 `|` 将「当前 provider 组」与「规划中」分开。

### 2.2 风险提示 banner（ADR-29）
- 红底警示条，固定文案：
  > ⚠️ 风险提示：此提供商使用的订阅 / OAuth 会话未获官方授权用于代理 / 路由器使用。账户可能被限制或封禁。使用风险自负。
- 常驻 Auth tab 顶部，不随 provider 增减。

## 3. 账号卡片（Auth Account Card）

### 3.1 结构（自上而下）

```
┌───────────────────────────────────────────────┐
│ [头像] [● 名称  [计划tag]]   [✎] [⏻] [🗑]       │
│        [邮箱]                                  │
├───────────────────────────────────────────────┤
│ 限额块 1：◔ 限额 · 月限额    [0% 已用]           │
│   [░░░░░░░░░░░]  重置 9/8 15:03 · codex         │
├───────────────────────────────────────────────┤
│ ◎ 可用模型（登录/12h 自动同步 · 全量支持）          │
│   [gpt-5.5] [gpt-5.6-sol] [+3]                │
├───────────────────────────────────────────────┤
│ meta chips：P0·W1  同步于 今天 07:57  刷新 07:57 │
├───────────────────────────────────────────────┤
│ [↻ 刷新令牌] [⇅ 同步模型] [⬇ 写回 CLI]（一行均分） │
└───────────────────────────────────────────────┘
```

### 3.2 元素明细
- **头像**：provider 色渐变圆角方块（codex 绿），内为 ⌘ 或 provider 图标。
- **名称 + 计划 tag**：名称可编辑（`label` 通用列，ADR-27）；计划 tag（Plus/Pro/免费）来自 id_token 的 `chatgpt_plan_type`。
- **邮箱**：从 id_token `email` claim 解析（小字，muted）。
- **状态点**：绿=正常、灰=停用/失效、琥珀=限额耗尽。配套状态 tag：`已失效`（红底）、`已踢出路由`（琥珀）。
- **限额块**：每块 = 标题（`◔ 限额 · <标签>`，标签只支持 **5H限额 / 周限额 / 月限额** 三种，按 `window_minutes` 近似匹配，其它时长显示裸「限额」）+ 百分比 + 进度条 + 底部「重置 <具体时间点> · <limit_id>」（本地化月/日/时/分，如 `9/8 15:03`）。色阶：绿(低) → 琥珀(中) → 红(100%，已踢出路由)。**上游不返回限额字段则不渲染限额块**（ADR-28）；空窗口（仅 `used-percent:0`、无时长无重置）也不渲染；**上游未返回 `reset_at` 则不显示重置行**。
- **模型区**：只读 tag 列表（全量支持，无勾选，ADR-8/21）；注明同步来源与节奏。
- **meta chips**：`P0·W1`（priority·weight，可编辑，ADR-26）、`同步于 <时间>`、`刷新 <时间>`。
- **底部操作行**：`↻ 刷新令牌` `⇅ 同步模型` `⬇ 写回 CLI` 三按钮一行均分（`flex:1`）。
- **右上动作列**：`✎ 编辑` `⏻ 启停用` `🗑 删除` 三图标**一行横排**。

### 3.3 状态变体
| 状态 | 状态点 | 限额块 | 底部操作 |
| --- | --- | --- | --- |
| 正常启用 | 绿 | 正常进度条 | 刷新/同步/写回 |
| 限额耗尽（踢出路由） | 琥珀 | 100% 红条 +「已踢出路由 · 重置 1h 后」 | 刷新/同步/写回 |
| 失效（令牌过期） | 灰 | 红色警示块「⚠ 令牌已失效 · 需重新登录」+ 自动刷新失败说明 | `🔑 重新登录`(宽) + `↻ 刷新` + `⬇ 写回` |

### 3.4 空槽卡片
- 虚线边框卡片：`＋ 登录 Codex 账号` + 说明「浏览器 OAuth 登录（PKCE）或从本机 ~/.codex/auth.json 导入」+ `🔑 登录` `⇧ 导入` 按钮。

## 4. 弹窗交互

### 4.1 编辑账号弹窗（✎）
- 字段：账号名称（text）、优先级 priority（number，≥0）、权重 weight（number，≥1）。
- 顶部标识条：头像 + 邮箱 + `plan: <plan> · 账号级限额`。
- 操作：`取消` / `保存`（保存后名称与 P·W chip 同步）。

### 4.2 同步模型弹窗（⇅ 同步模型）
- 标题：`同步模型 · <账号名>`；副注「来自上游 /models 实时返回 · 登录/12h 自动同步 · 全量支持（只读）」。
- 打开先显示 spinner「同步中…」，随后列出模型（`✓ <model> 可用`）。
- 操作：`关闭`。**只读，无勾选**（ADR-8）。

### 4.3 登录流程弹窗（🔑 登录）
- 标题 `登录 Codex 账号`，标识条 + 说明「浏览器 OAuth 授权 · PKCE · 消耗订阅额度」。
- 分步展示五步（每步有状态：待定 → 进行中 → ✓ 完成）：
  1. 启动本地回调服务器（随机端口，生成 PKCE code_verifier / code_challenge / state）
  2. 打开浏览器授权（client_id · redirect_uri=localhost · code_challenge）
  3. 用户在浏览器完成登录（回跳 localhost 带回 code）
  4. 换令牌 · 入库（code + code_verifier 换 token → 按 account_id 覆盖入库）
  5. 同步模型列表（GET /models → 更新快照）
- 第 2 步时提示「已在浏览器打开授权页，请在浏览器完成登录」。
- 完成后：成功提示 + `完成` 按钮；空槽变新卡片（toast 提示）。

### 4.4 删除账号弹窗（🗑）
- 二次确认：标题 `删除账号 · <账号名>`，标识条（头像 + 邮箱 + plan tag）。
- 文案：「**是否删除该账号？** 删除后此账号不再参与路由。仅从本应用移除，不影响本机 Codex CLI 登录态。」——`取消` / `确认删除` 两按钮，危险色确认键。
- 删除动作 = **纯本地移除**：`auth_logout` 删除账号行 + 模型快照，不调用 provider revoke 端点（ADR-38）；确认后卡片移除 + toast「已删除」。若检测到 `~/.codex/auth.json` 含该账号副本，可附一句「已写回本机 Codex CLI，可另行 `codex logout` 注销」。

### 4.5 其它
- **导入 auth.json**（⇧）：弹文件选择框，默认选中 `~/.codex/auth.json`（`$CODEX_HOME` 优先，与 ADR-2 C 一致）；选中后 toast「正在读取 <实际路径> …」（ADR-2 C / ADR-24）。
- **写回 CLI**（⬇）：toast「已写入 ~/.codex/auth.json」（ADR-18）。
- **重新登录**（失效卡片）：toast「将打开浏览器进行 OAuth 登录」（ADR-25）。

## 5. 与现有页面的一致性
- Auth 卡片网格 ↔ `ApiKeysPage` 的 `xl:grid-cols-2` 卡片网格 + `surface rounded-[24px]`。
- Provider pill 一排 ↔ `UsagePage` APP_TABS 彩色 pill（codex 绿 / claude 紫…）。
- API|Auth tab ↔ `SettingsPage` underline tab 风格。
- 图标：复用 lucide（`Power`/`Trash2`/`Edit`/`RefreshCw`/`Download`/`Upload` 等）。
- 颜色 token：按实际 `src/App.css` 走——主色 `--color-primary:#2f6fed`、边框 `--color-border:rgba(15,23,42,0.08)`，危险/成功/警告用 `--color-destructive/#dc4c64`、`--color-success/#1f8f5f`、`--color-warning/#c48a21` 或对应 Tailwind palette；**不引用不存在的 `--emerald`/`--amber`/`--red` 变量**（校准 C-4）。
