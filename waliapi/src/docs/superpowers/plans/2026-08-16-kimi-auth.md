# Kimi Code Auth 登录与 Auth Provider 通用化实施计划

> **For agentic workers:** 按任务顺序实施。每个任务先写或更新失败测试，再改实现，再执行该任务列出的验证命令。不要把 Kimi 协议转换写进认证 Provider；Chat、Messages、Responses 之间的转换必须继续由现有 `CodecRegistry` 完成。

**Goal:** 在不破坏现有 Codex Auth 的前提下，为 WaLiAPI 新增 Kimi Code OAuth Device Authorization 登录、令牌刷新、模型同步、Auth 账号路由、流式与非流式调用，以及对应的多 Provider UI。

**Architecture:** 保留现有 `Provider`、`ProviderRegistry`、`ProviderPayload`、`AuthService`、`auth_accounts` 数据表和协议 codec。新增 Kimi Provider；静态 `ProviderSpec` 只保存 renderer-safe 能力，Kimi 的 wire profile 由 `/models` 的逐模型 `protocol` 元数据决定；RoutePlan 在模型映射校验后把可信的 base URL、protocol、endpoint、framing 固化到 candidate/attempt；登录 session 从 Codex 专用 runner 改成 provider-neutral runner；重新登录通过 AuthService 的受控上下文和现有每账号刷新锁更新，命令层不读取凭据。

**Tech Stack:** Rust、Tokio、Reqwest、Tauri v2、SQLite、React、TypeScript、Tailwind、现有三协议 CodecRegistry。

## 1. 交付范围

本计划必须交付以下完整能力：

1. Kimi Code 设备码登录。
2. 浏览器自动打开与手动授权 URL、user code 展示。
3. 登录取消、拒绝、设备码过期重启、总超时。
4. access token 和 refresh token 安全持久化。
5. refresh token rotation、请求前刷新、401 单次强制刷新重试。
6. Kimi `/models` 同步，并持久化逐模型 `protocol` 路由元数据。
7. Kimi Auth 账号参与 `/v1/chat/completions`、`/v1/responses`、`/v1/messages` 路由。
8. Kimi 流式与非流式响应通过现有 codec 转换。
9. Codex Auth 登录、导入、导出、刷新、模型同步和路由回归不变。
10. Provider 选择、Kimi 登录进度、Kimi 账号卡片和重新登录 UI。
11. Rust 单元测试、路由测试、executor 集成测试和前端构建验证。

本计划不交付以下能力：

1. 不实现 Kimi CLI credentials 文件导入。
2. 不实现 Kimi credentials JSON 导出。
3. 不实现未经官方源码确认的 Kimi quota endpoint。
4. 不新增 Kimi 专用 Chat、Messages、Responses 转换器。
5. 不把 Kimi Code 订阅接口与 Moonshot Open Platform API Key 接口混用。
6. 不解析未公开的 access token JWT claim 来猜测用户 ID、email 或组织 ID。
7. 不新增数据库 migration。

### 2.2 OAuth 协议

Kimi Code 使用 RFC 8628 OAuth 2.0 Device Authorization Grant，不使用 Codex 的 loopback callback、state 或 PKCE。

固定配置：

```text
client_id = 17e5f671-d194-4dfb-9706-5516cb48c098
oauth_host = https://auth.kimi.com
device_authorization_path = /api/oauth/device_authorization
token_path = /api/oauth/token
managed_api_base = https://api.kimi.com/coding/v1
```

Device authorization：

```http
POST /api/oauth/device_authorization
Content-Type: application/x-www-form-urlencoded
Accept: application/json

client_id=17e5f671-d194-4dfb-9706-5516cb48c098
```

成功响应必须验证：

```text
user_code: non-empty string
device_code: non-empty string
verification_uri_complete: non-empty string
verification_uri: optional string
expires_in: optional positive number
interval: optional positive number, default 5
```

Token polling：

```http
POST /api/oauth/token
Content-Type: application/x-www-form-urlencoded
Accept: application/json

client_id=17e5f671-d194-4dfb-9706-5516cb48c098
device_code=<device_code>
grant_type=urn:ietf:params:oauth:grant-type:device_code
```

轮询状态：

| 服务端状态 | 客户端动作 |
|---|---|
| HTTP 200 且有 `access_token` | 严格解析 token，结束登录 |
| `authorization_pending` | 按当前 interval 继续 |
| `slow_down` | 当前 interval 永久增加 5 秒后继续 |
| `expired_token` | 重新申请 device authorization；仍受 15 分钟总 deadline 限制 |
| `access_denied` | 结束并返回稳定的授权拒绝错误 |
| HTTP 5xx | 返回可重试登录错误，不持久化凭据 |
| 其他错误 | 返回 token exchange 错误，不向 UI 暴露原始响应 |

总登录 wall-clock deadline 为 15 分钟。取消信号必须中断 HTTP 等待或 sleep，不得等到下一个轮询周期才退出。

Refresh：

```http
POST /api/oauth/token
Content-Type: application/x-www-form-urlencoded
Accept: application/json

client_id=17e5f671-d194-4dfb-9706-5516cb48c098
grant_type=refresh_token
refresh_token=<persisted_refresh_token>
```

Token 成功响应要求：

```text
access_token: required non-empty string
refresh_token: required non-empty string
expires_in: required positive finite number
scope: optional string, default empty
token_type: optional string, default Bearer
```

过期时间写成 UTC RFC3339：

```text
expires_at = now_utc + expires_in seconds
```

刷新错误分类：

| 条件 | ProviderError |
|---|---|
| HTTP 401、403、`invalid_grant` | `Unauthorized` |
| HTTP 429、500、502、503、504 | `Retryable`，provider 内最多 3 次，1 秒和 2 秒退避 |
| DNS、连接、TLS、30 秒 HTTP timeout | `Retryable`，同样最多 3 次 |
| 成功响应字段缺失或类型错误 | `Protocol` |

### 2.3 Kimi Code 业务接口

Kimi Code Auth 账号使用：

```text
GET  https://api.kimi.com/coding/v1/models
POST https://api.kimi.com/coding/v1/chat/completions
POST https://api.kimi.com/coding/v1/messages?beta=true
```

它不是：

```text
https://api.moonshot.cn/v1
https://api.moonshot.ai/v1
https://chatgpt.com/backend-api/codex
```

`/models` 按 OpenAI 格式读取 `data[].id`，并读取可选的 `data[].protocol`。锁定的官方 `kimi-code` commit 已明确支持至少两种逐模型协议：

| `/models` 的 `protocol` | Wire profile | 固定业务 URL | Auth header | Non-stream framing |
|---|---|---|---|---|
| 缺失或 `kimi` | OpenAI Chat Completions | `https://api.kimi.com/coding/v1/chat/completions` | `Authorization: Bearer` | JSON |
| `anthropic` | Anthropic Messages beta | `https://api.kimi.com/coding/v1/messages?beta=true` | `x-api-key` | JSON |

这里的 `protocol` 是服务端模型目录给出的非 secret 路由元数据，不是 renderer、账号 attributes 或下游请求可控制的配置。未知非空协议必须 fail closed：该模型不能标记为 available，也不能回退到 Chat。

## 4. 目标数据结构与边界

### 4.1 ProviderKind

在 `src-tauri/src/auth_provider/types.rs` 中改为：

```rust
#[derive(Clone, Debug, Eq, Hash, PartialEq)]
pub enum ProviderKind {
    Codex,
    Kimi,
    Other(String),
}
```

序列化字符串固定：

```text
Codex -> codex
Kimi  -> kimi
```

`From<&str>` 必须把 `kimi` 映射为显式枚举，未知值仍进入 `Other(String)`，由 registry 决定是否可用。

### 4.2 静态 ProviderSpec 与逐模型 AuthRouteProfile

新增 `src-tauri/src/auth_provider/spec.rs`，内部定义：

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize)]
#[serde(rename_all = "snake_case")]
pub enum AuthNonStreamFraming {
    Json,
    ForcedResponsesSse,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum AuthLoginMode {
    BrowserCallback,
    DeviceCode,
}

#[derive(Clone, Copy, Debug)]
pub struct ProviderSpec {
    pub kind: &'static str,
    pub display_name: &'static str,
    pub icon_key: &'static str,
    pub login_mode: AuthLoginMode,
    pub supports_import: bool,
    pub supports_export: bool,
    pub supports_quota: bool,
}
```

静态 Spec 固定值：

| 字段 | Codex | Kimi |
|---|---|---|
| `kind` | `codex` | `kimi` |
| `display_name` | `Codex` | `Kimi Code` |
| `icon_key` | `codex` | `moonshot` |
| `login_mode` | `BrowserCallback` | `DeviceCode` |
| `supports_import` | `true` | `false` |
| `supports_export` | `true` | `false` |
| `supports_quota` | `true` | `false` |

提供以下纯函数：

```rust
pub fn provider_spec(kind: &ProviderKind) -> Option<&'static ProviderSpec>;
pub fn provider_spec_by_name(name: &str) -> Option<&'static ProviderSpec>;
pub fn registered_provider_specs() -> &'static [&'static ProviderSpec];
```

`spec.rs` 不创建 HTTP client，不读数据库，不解析 token，也不依赖 `core::route_plan`。它只作为 provider registry 和 renderer-safe provider list 的稳定真源。

在 `db/models.rs` 扩展已有 JSON 快照，不新增 migration：

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct ModelState {
    pub id: String,
    pub status: String,
    pub unavailable: bool,
    pub next_retry_after: Option<String>,
    pub last_error: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub protocol: Option<String>,
}
```

旧 Codex 快照没有 `protocol` 时必须正常反序列化；`ModelStates.version` 暂不升级，因为这是向后兼容的可选字段。

路由层定义内部的不可变解析结果；类型放在 `core`，避免 auth provider 反向依赖完整路由层：

```rust
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct AuthRouteProfile {
    pub provider: String,
    pub native_base_url: String,
    pub upstream_protocol: UpstreamProtocol,
    pub upstream_endpoint: String,
    pub non_stream_framing: AuthNonStreamFraming,
}
```

解析矩阵：

| Provider + model protocol | base URL | `UpstreamProtocol` | endpoint | framing |
|---|---|---|---|---|
| Codex + missing | `https://chatgpt.com/backend-api/codex` | `Responses` | `responses` | `ForcedResponsesSse` |
| Kimi + missing/`kimi` | `https://api.kimi.com/coding/v1` | `OpenAI` | `chat_completions` | `Json` |
| Kimi + `anthropic` | `https://api.kimi.com/coding` | `Anthropic` | `messages_beta` | `Json` |

`messages_beta` 是内部语义 endpoint；只有 KimiProvider 能把它映射为固定的 `/v1/messages?beta=true`。普通 Anthropic Channel 的 `messages` 行为不变。

模型映射必须在 RoutePlan 阶段 fail closed：直接命中模型时读取该模型的 profile；alias 有多个目标时，只有所有可选目标解析为完全相同的 profile 才允许形成一个 candidate。混合 `kimi`/`anthropic` 目标必须记入 `config_errors` 并排除，不能等随机选中目标后改变已分组的协议。`build_prepared_attempt` 仍可按当前逻辑随机选择同 profile 的最终上游模型。

### 4.3 LoginRuntime

现有 `LoginRuntime` 只有 `open_browser`，不足以支持设备码、取消和进度。扩展为：

```rust
#[async_trait]
pub trait LoginRuntime: Send + Sync {
    async fn open_browser(&self, url: &str) -> Result<(), ProviderError>;
    async fn set_step(&self, step: LoginStep);
    async fn present_device_authorization(
        &self,
        verification_url: &str,
        user_code: &str,
        expires_at: Option<String>,
    ) -> Result<(), ProviderError>;
    fn is_cancelled(&self) -> bool;
    async fn cancelled(&self);
}
```

`LoginStep` 固定：

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum LoginStep {
    Preparing,
    Authorizing,
    Waiting,
    Exchanging,
    Saving,
    Syncing,
}
```

生产 `SessionLoginRuntime` 连接 `LoginSessions` 和 cancellation receiver。新增方法不提供会静默吞掉交互的默认实现；Task 2 必须在同一个提交内更新 `SessionLoginRuntime`、Codex runtime 和所有测试 runtime，保持全量编译。

### 4.4 Provider trait 登录边界

保留 Provider 负责具体 OAuth，但把 session commit gate 留在命令层。重新登录目标由 AuthService 解析，命令层只传本地账号 ID，绝不读取 `payload_json`：

```rust
pub enum LoginTarget {
    New,
    Replace { local_account_id: String },
}

pub struct ProviderLoginContext {
    pub replacement: Option<ReplacementContext>,
}

pub struct ReplacementContext {
    pub local_account_id: String,
    pub provider_account_id: String,
    pub previous_payload: ProviderPayload,
}

pub async fn authenticate(
    &self,
    kind: ProviderKind,
    target: LoginTarget,
    runtime: &dyn LoginRuntime,
) -> Result<AuthenticatedLogin, ProviderError>;

pub async fn persist_authenticated(
    &self,
    authenticated: AuthenticatedLogin,
) -> Result<AuthAccountSummary, ProviderError>;
```

`Provider::login` 同步改为接收 `&ProviderLoginContext`。对于 Kimi replacement，Provider 只能从其中的脱敏边界对象读取旧 payload 并复用 `device_id`；Codex 可忽略 replacement context。`AuthenticatedLogin` 保存 `kind`、`LoginResult` 和受控的 replacement 元数据，防止调用者在 authenticate 后替换目标 ID。

现有 `AuthService::login` 改成组合调用，保持兼容：

```text
authenticate(kind, LoginTarget::New, runtime) -> persist_authenticated
```

异步登录 session 使用：

```text
authenticate(kind, target, runtime)
-> LoginSessions::begin_save
-> persist_authenticated
-> sync_models
```

新建账号继续使用 `(provider, provider_account_id)` upsert。replacement 必须使用独立保存路径：以 `local_account_id` 获取和 refresh 完全相同的账号 mutex；锁内重新读取账号，重新校验 provider、provider account ID 和 Kimi `device_id`，然后通过 repository 的 update-by-local-id + 乐观前置条件原子更新，不调用通用 conflict upsert。该原子更新必须同时把 `model_states_json` 重置为空快照、把 `last_models_sync_at` 置空，避免登录后模型目录或 protocol 已变化时继续路由旧快照；后续 sync 成功才重新启用路由。账号被删除、provider/device ID 改变或前置条件失败时 fail closed。这样取消 commit gate 防止取消后落库，账号 mutex 则防止 re-login 与 refresh token rotation 互相覆盖。

### 4.5 Kimi ProviderPayload

内部 JSON 固定为：

```json
{
  "version": 1,
  "access_token": "secret",
  "refresh_token": "secret",
  "token_type": "Bearer",
  "scope": "",
  "expires_at": "2026-08-16T12:00:00Z",
  "expires_in": 3600,
  "device_id": "32-character-lowercase-hex"
}
```

字段规则：

| 字段 | 规则 |
|---|---|
| `version` | 固定 `1` |
| `access_token` | required non-empty string |
| `refresh_token` | required non-empty string |
| `token_type` | 缺失时 `Bearer` |
| `scope` | 缺失时空字符串 |
| `expires_at` | UTC RFC3339，供现有 `ProviderPayload::expires_at()` 使用 |
| `expires_in` | positive integer seconds，用于诊断和将来刷新策略 |
| `device_id` | 登录前生成，刷新和业务请求始终复用 |

禁止放入 payload：

```text
device_code
user_code
verification_uri
verification_uri_complete
error_description
HTTP response body
```

### 4.6 Kimi 账号身份

官方 OAuth 不返回稳定 account/profile ID。因此：

1. 新建账号时生成独立 `device_id`。
2. `LoginResult.account_id` 使用 `device_id`。
3. `LoginResult.label` 使用 `Kimi Code`。
4. `attributes` 使用：

```json
{
  "plan_type": "kimi_code",
  "identity_source": "local_device_id"
}
```

5. 重新登录时，命令层只把 `replace_account_id` 封装成 `LoginTarget::Replace`；AuthService 加载现有 Kimi 账号、校验 provider，并通过 `ProviderLoginContext` 把旧 payload 交给 KimiProvider。
6. KimiProvider 从受控 context 复用原 `device_id`，登录结果沿用同一个 provider account ID；如果账号不存在、provider 不是 `kimi`、payload 没有合法 `device_id`，在发起 OAuth 请求前拒绝。
7. 保存 replacement 时取得与 refresh 相同的账号锁并按 local ID 条件更新；不得使用通用 upsert，也不得让旧 refresh 结果覆盖新登录凭据。

## 5. 请求和路由矩阵

### 5.1 Provider/模型原生端点

| Provider / model profile | Native protocol | Native endpoint | Auth header | Non-stream framing |
|---|---|---|---|---|
| Codex | Responses | `/responses` | Codex 现有 Bearer/actor headers | 上游强制 SSE，再聚合 |
| Kimi `kimi`/missing | OpenAI Chat | `/chat/completions` | `Authorization: Bearer <access_token>` | 普通 JSON |
| Kimi `anthropic` | Anthropic Messages | `/v1/messages?beta=true` | `x-api-key: <access_token>` | 普通 JSON |

### 5.2 下游入口到上游

| 下游 EndpointKind | Codex | Kimi Chat profile | Kimi Anthropic profile |
|---|---|---|---|
| `ChatCompletions` | Conversion: Chat -> Responses | Native: Chat -> Chat | Conversion: Chat -> Messages |
| `Responses` | Native: Responses -> Responses | Conversion: Responses -> Chat | Conversion: Responses -> Messages |
| `Messages` | Conversion: Messages -> Responses | Conversion: Messages -> Chat | Native: Messages -> Messages |
| `CountTokens` | 不形成 Auth group | 不形成 Auth group | 不形成 Auth group |
| `Embeddings` | 不形成 Auth group | 不形成 Auth group | 不形成 Auth group |

Auth 账号继续保持当前行为：即使 `cross_protocol_codec` rollout flag 关闭，也可形成其已支持的 conversion group。不要在本任务改变 Codex Auth 的 rollout 语义。

### 5.3 非流 executor

Codex：

```text
encoded Responses body
-> force stream=true
-> Provider::outbound
-> Responses SSE
-> ResponsesEventAccumulator
-> complete Responses JSON
-> prepared codec decode_non_stream
-> downstream JSON
```

Kimi Chat 或 Anthropic profile：

```text
encoded Chat/Messages body
-> force stream=false
-> remove stream_options when present
-> Provider::outbound
-> provider-native JSON
-> prepared codec decode_non_stream
-> downstream JSON
```

### 5.4 流 executor

Kimi Chat profile：

```text
encoded Chat body
-> force stream=true
-> merge stream_options.include_usage=true
-> Provider::outbound
-> Chat SSE
-> existing first-frame validation
-> existing prepared streaming codec
-> downstream Chat, Responses, or Messages SSE
```

Kimi Anthropic profile 使用相同的 Json/SSE executor 分支，但 body 为 Messages，固定请求 `/v1/messages?beta=true`，不得注入 Chat 的 `stream_options`。

## 8. 关键不变量

实现和 review 必须逐条检查：

1. **认证与协议转换分离。** KimiProvider 不调用或复制 Chat/Messages/Responses 转换逻辑。
2. **固定上游。** Kimi OAuth、两个业务 base/endpoint 和 beta query 不能由 renderer、请求 body、账号 attributes 或 downstream headers 覆盖；逐模型 protocol 只能来自 provider `/models` 快照。
3. **凭据不越界。** ProviderPayload 不进入 command DTO、Debug、日志或前端。
4. **设备码不落库。** device code、user code 和 verification URL 不进入 `payload_json`。
5. **取消不落库。** cancel 和 begin-save 由同一个 session commit gate 串行化。
6. **刷新单飞。** 复用共享 `AppState.auth_service` 的每账号 mutex；不要在请求路径创建独立长期 AuthService。
7. **重新登录与刷新互斥。** replacement 保存使用同一账号 mutex 和 local-ID 条件更新，不能与 refresh token rotation 互相覆盖。
8. **401 只重试一次。** 第二次 401 必须终止并进入账号无效逻辑。
9. **模型快照为空不路由。** 登录成功但 `/models` 失败时保留账号并返回 warning，不让账号参与路由。
10. **重新登录先失效旧模型。** replacement 保存新凭据时原子清空旧模型快照，只有新 `/models` sync 成功后才恢复路由。
11. **逐模型协议 fail closed。** 未知 protocol 或混合协议 mapping 不形成 candidate，不能默认成 Chat。
12. **Attempt 元数据是唯一执行依据。** executor 不查库、不读 payload/attributes、不按 Content-Type 猜 framing。
13. **未知 provider fail closed。** 不能回退 Codex spec、Codex URL 或 Codex parser。
14. **Kimi 无 quota 不等于无限。** UI 隐藏 quota 块；路由只根据 status、disabled、模型快照和已有通用 cooldown 判断。
15. **Codex 回归不变。** PKCE、callback ports、import/export、Responses forced SSE 全部保留。
16. **Kimi Code 与 Moonshot Open Platform 分离。** Auth 账号只使用 `api.kimi.com/coding`。

16. 原始 OAuth response 是否可能通过 Debug、tracing 或 panic message 泄漏。
17. terminal session 是否清空 verification，UI 是否可能把 verification 对象写入 console。
18. Kimi 无 quota 时是否错误显示满额或无限。
19. 未知 provider 是否 fail closed。
20. legacy `auth_login(kimi)` 是否在网络前稳定拒绝。
21. 每个提交是否执行 `cargo check --all-targets`，所有新增分支是否有离线 mock 测试。

---

## 11. 推荐提交边界

为便于 review，按以下顺序拆分提交：

1. `refactor(auth): add provider metadata and model protocol snapshot`
2. `refactor(auth): add generic login context and locked replacement persistence`
3. `feat(auth): implement Kimi device OAuth and refresh`
4. `feat(auth): add unregistered Kimi backend and protocol-aware model discovery`
5. `refactor(route): carry model-level auth profiles into prepared attempts`
6. `refactor(executor): execute auth attempt framing and register Kimi`
7. `feat(ui): add Kimi auth login and provider-aware accounts`
8. `test(auth): cover Kimi routing replacement refresh and protocol flows`

每个提交都必须执行至少 `cargo check --all-targets` 并保持可编译；提交 4 不注册 Kimi，提交 6 完成 executor 垂直切片后才注册。不得把 credential fixture、真实账号文件、数据库文件或日志提交到仓库。
